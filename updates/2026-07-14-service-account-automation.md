The Enterprise Portal default template now offers an optional Automation section.
Adopt this update to add it to your content repo for customers who use service accounts in CI/CD, deployment scripts, or other non-browser install workflows.
The section includes two pages:

- **API Reference**: Renders the built-in service account API reference for customer automation.
  It documents authentication, request and response shapes, accepted install option values, errors, and download endpoints.
- **Workflow Guide**: Shows an example service account install workflow.
  It includes creating install options, fetching instructions, saving the install options ID, and downloading artifacts.

The pages use built-in MDX components that update with the Enterprise Portal application.
Vendors can keep, customize, move, or remove the pages like any other content repo page.

The API reference is generated by the Enterprise Portal application.
Future endpoint documentation updates can appear without vendors manually rewriting the page content.
The workflow guide is intentionally example-oriented, so vendors can edit the surrounding page copy, rename the section, or remove the guide if they already publish their own automation docs.

## What changed

- Added `pages/automation/api-reference.md` with the `<APIReference />` component.
- Added `pages/automation/workflow-guide.md` with the `<HeadlessWorkflowGuide />` component.
- Added an Automation group to `toc.yaml`.

## Recommended adoption

Review the Automation section before adopting the update.
Adopt it when customers use service accounts for install automation, or skip it if you document automation elsewhere.

If you adopt the pages, review the generated API reference description and the workflow guide copy in your portal preview.
Adjust the page titles or surrounding text so the pages use your customer's terminology, such as how your docs describe service accounts, install profiles, and automation.
